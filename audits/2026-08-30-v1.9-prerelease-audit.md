## Part 1 — Security & PII Report

**Findings: 0 Critical · 1 High · 3 Medium · 4 Low**

---

### HIGH

#### H-1 — GPS snapshot not excluded from iCloud backup
**File:** `PoCSquat/Services/Walk/ActiveWalkSnapshot.swift:94–103`

The `active-walk-snapshot.json` file is written to `applicationSupportDirectory`. This directory is **not** auto-excluded from iCloud backup — only `Caches/` and `tmp/` are excluded by default. The snapshot contains full GPS breadcrumbs, timestamps, step count, pet IDs, and elapsed time.

The `clear()` path is called reliably on `stop()`, `declineRestore()`, and after salvage, but if the app crashes between `writeSnapshot()` and `clear()` in `stop()`, the file survives and gets backed up on the next iCloud sync.

**Suggested fix:** After constructing the file URL, mark it as excluded from backup:
```swift
var url = dir.appendingPathComponent("active-walk-snapshot.json")
var values = URLResourceValues()
values.isExcludedFromBackup = true
try? url.setResourceValues(values)
return url
```

### MEDIUM

#### M-1 — `NSRemindersUsageDescription` is orphaned
**File:** `PoCSquat/Info.plist:52–53`

`WalkSchedulerService.swift` uses `EKEventStore` only for calendar events (`.event` entity type, `requestWriteOnlyAccessToEvents()`). No `EKReminder` or `.reminder` entity type usage exists anywhere in the codebase. The Reminders key requests a permission that has no corresponding feature.

Unnecessary permission keys erode user trust and can trigger App Store Review scrutiny.

**Suggested fix:** Remove `NSRemindersUsageDescription` from Info.plist.

---

#### M-2 — Two parallel scheduling implementations; only one surfaces permissions
**Files:** `PoCSquat/Views/Walk/ScheduleWalkSheet.swift`, `PoCSquat/Services/Walk/WalkSchedulerService.swift`

`ScheduleWalkSheet` (shown from `ActivitySummaryView`) uses `UNCalendarNotificationTrigger` — no calendar permission needed. `WalkSchedulerService` uses EventKit (calendar permission needed) but is not called from `ScheduleWalkSheet`. If `WalkSchedulerService` has no other reachable UI surface, `NSCalendarsUsageDescription` and `NSCalendarsWriteOnlyAccessUsageDescription` are claimed for a background service with no active UI path.

**Suggested fix:** Confirm which scheduler each UI surface calls. If `WalkSchedulerService` is unreachable, consolidate to one mechanism and remove unused Info.plist keys. If it is reachable from another surface, document where.

---

#### M-3 — GPS snapshot persists indefinitely after a crash if user never re-launches
**File:** `PoCSquat/Services/Walk/ActiveWalkSnapshot.swift:107–115`

`loadAnyAge()` bypasses the 4-hour expiry and is only called by `salvageStaleWalkIfNeeded()`. After a crash, if the user never re-opens the app, the GPS snapshot file persists in Application Support with no age-based deletion. Combined with the iCloud backup gap in H-1, crash-time GPS data could survive in cloud storage without an upper time bound.

**Suggested fix:** Add a hard 24-hour expiry inside `loadAnyAge()`:
```swift
if let created = try? fileURL.resourceValues(forKeys: [.creationDateKey]).creationDate,
   Date().timeIntervalSince(created) > 86400 {
    clear(); return nil
}
```

---

### LOW

#### L-1 — `aps-environment: development` hardcoded in entitlements
**File:** `PoCSquat/PoCSquat.entitlements:6–7`

Xcode overrides this during standard archive/export, but any CI pipeline that skips Xcode's export step would leave APNs routing to the sandbox.

**Suggested fix:** Remove the key and let Xcode manage it automatically, or parameterize via `Versions.xcconfig` with `APS_ENV` per-configuration.

---

#### L-2 — Snapshot write failures silently swallowed
**File:** `PoCSquat/Services/Walk/ActiveWalkSnapshot.swift:101`

`try? data.write(to: fileURL, options: .atomic)` — disk-full or permissions errors are discarded. The user continues their walk with no checkpoint, and a subsequent crash means full session loss.

**Suggested fix:** Wrap in `do/catch` and emit a non-PII OSLog error: `log.error("Snapshot write failed")`. Do not include the file path in the log string.

---

#### L-3 — No explicit file protection class on snapshot write
**File:** `PoCSquat/Services/Walk/ActiveWalkSnapshot.swift:101–103`

The default protection is `.completeUntilFirstUserAuthentication` — appropriate for background writes during a walk. Relying on the implicit default makes intent invisible to future maintainers.

**Suggested fix:** After writing, explicitly set the attribute, or add a comment: `// Protection: .completeUntilFirstUserAuthentication (required for background location writes)`.

---

#### L-4 — Route name on Live Activity lock screen has no user opt-out
**File:** `PoCSquat/Activity/WalkActivityAttributes.swift:31` (`routeName` static attribute)

Route names are user-generated and can contain address-derived strings ("Home Loop", "1234 Oak St Park Run"). These appear on the lock screen in the Live Activity, visible to bystanders.

**Suggested fix:** Document as accepted risk, or offer a "Show route name on lock screen" privacy toggle in Settings.

## Part 2 — Accessibility Audit

**Findings: 4 High · 9 Medium · 5 Low**

---

### HIGH — Critical-path controls with no VoiceOver label

#### A-H1 — Stop walk button has no `accessibilityLabel`
**Files:** `PoCSquat/Views/Walk/ActiveSessionView.swift` (HUD), `PoCSquat/Views/Walk/ActiveMiniTile.swift:104–110`

Both the full-screen HUD stop button (`stop.circle.fill`) and the mini-tile stop button are icon-only with no label. VoiceOver announces the system symbol name ("stop circle fill, button"). A VoiceOver user cannot reliably end a walk.

**Suggested fix:**
```swift
Image(systemName: "stop.circle.fill")
    .accessibilityLabel("End walk")
// In ActiveMiniTile, prefer:
    .accessibilityLabel("End \(route.activityMode.noun)")
```

---

#### A-H2 — Pause/Resume button has no `accessibilityLabel` and no state announcement
**File:** `PoCSquat/Views/Walk/ActiveSessionView.swift` (HUD pause button)

The icon-only toggle changes between `pause.circle` and `play.circle.fill`, but neither state gets a label. VoiceOver reads the symbol name regardless of state.

**Suggested fix:**
```swift
Button { /* toggle */ } label: {
    Image(systemName: isPaused ? "play.circle.fill" : "pause.circle")
}
.accessibilityLabel(isPaused ? "Resume walk" : "Pause walk")
```

---

#### A-H3 — Dismiss chevron button has no `accessibilityLabel`
**File:** `PoCSquat/Views/Walk/ActiveSessionView.swift` (~line 278)

`Image(systemName: "chevron.down")` in a button with no label. VoiceOver reads "chevron down, button."

**Suggested fix:** `.accessibilityLabel("Minimize session")`

---

#### A-H4 — `ActiveMiniTile` reopen button has no `accessibilityLabel`
**File:** `PoCSquat/Views/Walk/ActiveMiniTile.swift:60–80`

The main tappable area to restore the walk session has no label or hint indicating what the tap does.

**Suggested fix:**
```swift
.accessibilityLabel("Return to \(route.name)")
.accessibilityHint("Opens the active session view")
```

### LOW

#### A-L1 — Fixed font sizes in Live Activity don't scale with Dynamic Type
**File:** `WocketWidget/WocketWidgetLiveActivity.swift:176–200`

`font(.system(size: 9))`, `font(.system(size: 10))`, `font(.system(size: 13))` are hardcoded. Nothing scales at Accessibility text sizes.

**Suggested fix:** Replace with semantic sizes: `.font(.system(.caption2, design: .monospaced))`, `.font(.caption)`, `.font(.body)`.

---

#### A-L2 — `.earthMuted` text approaches AA minimum contrast at caption sizes
**Files:** `ActiveSessionComponents.swift`, `ActiveSessionView.swift` (stat cell labels)

`.earthMuted` (~rgb 140,140,133) on `.earthBg` (~rgb 26,31,28) yields approximately 4.9:1 contrast — just above the 4.5:1 WCAG AA threshold, but `caption2` (~11pt) sits dangerously close. System boldness could push the rendered value below 4.5:1.

**Suggested fix:** Increase the lightness of `.earthMuted` (e.g., to ~rgb 160,160,150 → ~6.5:1), or use `.earthCream.opacity(0.65)` for caption labels.
